# v3.1 数据质量报告

## 结论

v3.1 包含 530 条人工复审候选 Query、106 个答案组和 106 个规范化完整结论。每个答案组及每个完整结论最多对应 5 条 Query。

本报告只说明结构和来源检查结果，不代表人工复审结果。`status=not_pass` 和 `rank=0` 是用户指定的统一默认值，数据集没有据此判断 Query 质量。

## 已执行结构检查

- 每个答案组恰好五条 Query。
- 每组五种原始 Query 类型各一条。
- 同一规范化完整答案最多出现五次。
- Query ID 和规范化 Query 文本无重复。
- 必需、候选和禁止记忆 ID 均存在且角色不重叠。
- 来源任务和上下文 ID 均存在。
- 单记忆、多记忆、冲突和澄清结构符合轨道定义。
- 每题评分 JSON 可解析且权重合计为 1.00。
- 人工文本字段均非空；答案逻辑包含完整 Query、证据和结论。
- 人工复审字段位于最右侧，status 初始值全部为 not_pass，rank 初始值全部为 0。
- 已删除旧 `query_set.xlsx`，只保留一个 `query_set_human_review.xlsx` 人工视图。
- 工作簿公式错误扫描为 0，并完成 Human_Review、Review_Guide、Summary 和 Stats 视觉检查。

机器可复现结果见根目录 `validation_report.json`。

## 人工复审重点

人工应重点检查最右侧十列：

1. Query 是否自然且没有错误前提；
2. 必需记忆是否足以支持结论；
3. 候选或禁止记忆设置是否合理；
4. 预期结论是否完整回答用户；
5. 实际操作是否包含正确对象、步骤、范围、格式和输出；
6. 答案逻辑是否真正解释证据关系，而不是只重复答案；
7. 评分点及权重是否符合任务重要性；
8. 最后由人工填写 status 和 rank。

## 局限

底层仍只有 47 个 Calc 操作任务。v3.1 解决的是重复 Query 和人工复审困难，不解决操作数据量不足、多 App 覆盖和在线记忆更新问题。这些问题需要新的、有来源的操作数据。
