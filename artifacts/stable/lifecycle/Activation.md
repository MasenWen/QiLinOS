# Activation 算法分析

## 1. 稳定版本

Activation 负责让“当前 Observation 确实需要的记忆”重新变得活跃。当前稳定
入口是 `MemoryLifecycleEngine`，正式组合采用 **Weibull stability 与保守
Beta confidence**。前者记录记忆随时间衰退和每次激活后的寿命增长，后者估计
记忆证据本身是否可靠。

激活不是“查询与记忆有一点相似就增强”。系统先做 condition、object 和
attitude 的闭集匹配，再把语义匹配、confidence 和当前 stability 合成检索分数。
只有最终进入 Top-K 的记忆才获得增强；被考虑但没有选中的候选不会因为一次宽泛
查询而变强。

支持关系是第二种增强来源。新记忆与旧记忆之间存在明确 `supports` 或
`confirms` 关系时，两端或有向关系的目标端会获得一次较弱增强。普通相关、
先后、激活和因果边只保留在知识图谱中，不直接延长寿命。

## 2. 三层设计

### 2.1 查询与记忆匹配

Observation 已经包含标准化的 `condition`、`object` 和 `attitude`。Activation
不重新读取原始文本，也不再次调用麒麟 Embedding。匹配时 object 是主要信号，
condition 用于限制场景，attitude 用于阻止相反偏好相互激活。

三项完全一致时，condition、object 和 attitude 分别贡献 0.40、0.50 和
0.10。明确的相反 attitude 直接返回不匹配；condition 冲突把结果乘以 0.60，
object 冲突则乘以 0.35。最终语义匹配低于 0.45 时不进入候选。

自然语言伪过程：

> 从当前 `observation` 读取场景、对象和态度。
> 与每条 active 记忆的标准标签比较，先排除相反态度。
> object 决定主要相关性，condition 判断是否处于同一办公场景。
> 标签缺失表示证据不足，不自动当作冲突；明确冲突才施加惩罚。
> `match` 不足时停止，这条记忆既不返回，也不增强。

### 2.2 检索选择与边缘救援

通过语义门槛后，系统计算：

> `retrieval` 由 `match` 主导，再分别乘以 confidence 与 stability 的平滑因子。

confidence 因子保留 0.30 的底值，避免新证据较少的记忆完全失去机会；
stability 因子保留 0.55 的底值，避免刚刚衰退但高度匹配的记忆无法被救回。
检索分数低于 0.32 时不返回，其余候选排序后只选择 Top-K。固定测试使用
Top-2，运行入口默认允许 Top-3。

stability 低于正常遗忘门槛 0.15 时，记忆通常已经不应继续参与检索。但当它
仍高于绝对下限 0.05，且语义匹配达到 0.85 时，可以进行一次边缘救援。救援不是
无条件复活：低于 0.05 的记忆仍被遗忘，相似度不足的记忆也不会因接近查询而逃过
衰退。

自然语言伪过程：

> 先计算记忆在当前时间的 `stability`。
> 低于绝对下限时记为 forgotten。
> 处于边缘区间时，只有高度精确的 `match` 可以继续参加排序。
> 用 `match`、`confidence` 和 `stability` 得到 `retrievalScore`。
> 只对最终选中的 Top-K 记忆执行 `activate`。

### 2.3 激活增强

设计阶段完整实现了三种 stability：

- **Weibull 生存曲线**：用当前锚点、半衰尺度和曲线形状描述连续衰退。激活会
  同时提高锚点值和未来保留天数，当前值越低而匹配越明确，恢复幅度越大。
- **FSRS 幂律曲线**：沿用间隔学习中的 retrievability 与 stability 思路。
  每次激活把当前值拉回较高水平，并按遗忘程度扩张下一段间隔。
- **ACT-R 痕迹累积**：形成、查询激活和关系增强分别留下带时间的 trace，
  所有 trace 的衰减质量共同决定当前 stability。

三种方法都满足“随时间下降、正确激活后上升”，但在当前办公记忆中，
Weibull 对长期保留与清除旧任务的取舍最好，因此作为稳定方案。它在每次激活时
延长保留尺度，并把锚点向 1 推近；匹配越强、激活前越弱，寿命增长越明显。

stability 只描述“多久没有被需要”。confidence 描述“这条记忆先天有多可靠”。
当前保守 Beta 方法为文本证据设置较强先验，为日志设置较弱先验；支持证据增加
`alpha`，冲突和反例增加 `beta`，最终使用后验均值的保守下界。这样一条偶然日志
即使标签与查询完全一致，也不会轻易压过由用户自然语言形成的记忆。

### 2.4 关系增强

知识图谱中的 `supports` 和 `confirms` 可以增强 stability，并重新计算
confidence。无向支持同时作用于两端，有向支持只作用于目标端。关系权重决定增强
幅度，但关系增强弱于一次明确查询激活，避免相互连接的记忆在没有用户使用的情况
下无限自举。

`conflicts` 不增加 stability，而是进入 Beta 后验的反对证据，降低 confidence。
普通 `related`、`precedes`、`causes` 和 `activates` 不改变两个生命变量。

自然语言伪过程：

> 新关系到达时先判断 `relationType`。
> 明确支持则小幅延长 stability，并把关系证据加入 confidence。
> 明确冲突只降低 confidence，不伪造一次“被用户需要”的激活。
> 普通联系只留在图中，等待检索或后续推理使用。

## 3. 整体测评

完整重放使用先前形成的 191 条真实候选记忆，并加入短期陈旧、持续激活、
显式长期和中英文日志控制项，共维护 222 个状态。测试重放 530 条 Query，
不在 Activation 阶段调用 LLM 或 Embedding。

### 3.1 查询激活

| 指标 | 结果 |
| --- | ---: |
| Query 数量 | 530 |
| 存在对应记忆的 Query | 515 |
| 上游 Observation 已覆盖正确标签 | 408 |
| 找到正确记忆 | 394 |
| 对全部可评测 Query 的命中率 | **76.50%** |
| 上游标签正确后的生命周期命中率 | **96.57%** |
| 返回记忆数量 | 1039 |
| 其中语义正确 | 825 |
| 选择精确率 | **79.40%** |
| 边缘救援 | 1 |

76.50% 同时包含 79 次上游没有形成 Observation 和 28 次上游标签没有覆盖答案。
当上游已经给出可匹配的正确标签时，生命周期自身只漏掉 14 次，说明当前主要能力
是“正确记忆通常能够被激活”。选择精确率较低则说明 Top-K 中仍会混入兼容但不够
准确的旧记忆，这与 Recession 阶段遗忘偏慢有关。

### 3.2 增强行为

| 检查 | 数量 | 通过率 |
| --- | ---: | ---: |
| 定期接受正确查询的短期记忆继续存活 | 12 | **100%** |
| 显式长期记忆继续存活 | 12 | **100%** |
| 明确支持关系同时提升 stability 与 confidence | 93 | **100%** |
| 冲突关系降低 confidence | 8 | **100%** |

文本来源平均 confidence 为 0.7497，日志来源为 0.2944，差值 0.4553；同标签
控制查询正确选择了文本记忆。这表明来源先验确实参与最终选择，而不是仅保存在
状态中。AI 长期金标中，19 条最终应保留的记忆有 17 条仍处于 active，保留召回
为 89.47%。

九种 `3×3` 组合均完成相同重放。FSRS 最不容易丢失记忆，但会保留大量已无价值
内容；ACT-R 的痕迹解释直观，整体清理弱于 Weibull。三种 confidence 不改变相同
stability 下的最终遗忘状态，但会改变查询排序；综合长期金标和检索结果，稳定
版本采用 Weibull 与保守 Beta 下界。

### 3.3 性能

Weibull 与保守 Beta 的完整重放耗时约 397.57 ms，其中包括状态初始化、关系应用、
530 条查询、后期记忆加入和最终维护，折合每条查询不足 1 ms。该部分只有标准标签
集合运算和常数规模数值计算，不调用 LLM 或 Embedding，因此不属于 Observation
阶段的 300 至 500 ms 即时响应瓶颈。

## 4. 总结

稳定 Activation 的核心取舍是：先用 condition、object 和 attitude 防止错误
激活，再让 confidence 与当前 stability 参与排序，只增强真正进入 Top-K 的记忆；
明确支持提供较弱的图关系增强，普通相关不参与寿命自举。

当前版本已经能在上游标签正确时以 96.57% 的比例找到正确记忆，并能可靠实现查询
增强、关系增强、冲突降信和边缘救援。主要不足不是正确记忆无法激活，而是候选中
仍存在过期或重复记忆，选择精确率只有 79.40%。因此后续优化应优先减少错误共同
入选和重复激活，而不是继续增大每次激活的强度。
