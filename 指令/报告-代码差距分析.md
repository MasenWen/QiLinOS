## 二、代码缺失（报告有、代码无） ❌

### 缺失 1：四主标签结构化匹配管线（报告 5.2-5.5）—— 最高优先
- **缺失内容**：condition / obj / preferences / lastingtime 四主标签分类 → 各标签 Matching List → Embedding 语义匹配 → Calc MATCHING RATE（四标签加权综合）→ Thresholds & Filter 漏斗过滤。
- **代码现状**：仅有 `preference:*` 语义槽提取（`extractors.py`），无四标签分类器、无匹配率计算、无逐标签匹配列表。
- **影响**：报告第 5 章核心能力（结构化优先）无落地。

### 缺失 2：MATCHED 六字段输出结构（报告 6.1）
- **缺失内容**：KEY / CONDITION / OBJ / PREFERENCE / LASTTIME / TEXT INPUT 六字段输出模型与词/向量表示。
- **代码现状**：无 MATCHED 概念；现有 `models.py` 的 Observation/Evidence 结构不同（episode/证据链），不产出六字段。
- **影响**：报告第 6 章输出契约无落地。

### 缺失 3：知识图谱记忆 KG（报告 9）—— 次高优先
- **缺失内容**：ORGANIZED MEMORY KG：节点（NODES）与边（EDGE，AYES 肯定 / DENIES 否定）、STRONG/weak 记忆判定、强相关节点群、嵌入矩阵（OBS/OBC/LOGS × 四标签维度）、边权 = stronger matching → stronger EDGE。
- **代码现状**：记忆存储为向量库（MilvusLite）+ 评分模块（confidence/stability），**无图谱结构**（无节点/边/AYES/DENIES 概念）。
- **影响**：报告第 9 章知识图谱记忆（含冲突消解的 AYES/DENIES 语义）无落地；冲突检测（conflict.py）基于评分而非图谱边。

### 缺失 4：配置克隆无冲突约束（报告 11.3）
- **缺失内容**：配置克隆（clones）时 make sure no conflict 硬约束与冲突报告。
- **代码现状**：无克隆冲突检测逻辑。

### 缺失 5：遗忘曲线双维衰减（报告 10.2）—— 部分
- **缺失内容**：Confidence × Stability 双维随时间衰减的曲线函数。
- **代码现状**：`forgetting.py` 有 confidence/stability 评分与衰退流程，但**无随时间衰减的曲线化模型**（如指数/艾宾浩斯形态）。
